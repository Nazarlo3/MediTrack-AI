# Контрольний набір ЛР7

`cases.json`: 6 типових, 2 граничні (1/0 та 30/10), 2 некоректні (порожній опис/31 день). Перші п’ять — дослівні регресії ЛР6; шостий — попередній однозначний приклад травми. Нові граничні й невалідні входи зафіксовано перед запуском. Це синтетичні інженерні приклади, не медичні записи чи клінічна оцінка.

Потрібні backend/requirements-dev.txt, сервер із поточного коду на `http://127.0.0.1:18765`, AI_PROVIDER=groq та ключ лише на сервері.

```powershell
python backend/evaluation/lab7/run.py
python backend/evaluation/lab7/run.py --live
# Лише явний повтор невдалої перевірки, з окремим новим JSON:
python backend/evaluation/lab7/run.py --live --case b1_minimum
```

Без `--live` перевіряється набір/тотожність регресій, мережі немає. Повний прогін: 10 HTTP-запитів, із яких 8 звертаються до моделі. Автоматичних повторів немає. Таймер включає local HTTP/backend/Groq, не UI і не холодний старт Render. Results містить фактичні відповіді, час, очікування, model ID/параметри, хеші джерел і базовий Git commit. Фінальний commit не вигадується з базового HEAD.

Критерії до запуску: 8/8 категорій валідних запитів, 5/5 регресій, надані числа в поясненні та details_used=true, 2/2 відмови валідації. Невалідні входи не входять до accuracy. Технічний збій не вважається правильною категоризацією; окремий повтор не переписує першу спробу. [Фактичний підсумок](results/SUMMARY.md).
