# AI Component — MediTrack AI

## Призначення
Призначений для первинного текстового аналізу неідентифікаційного опису самопочуття користувача та класифікації його за обмеженим переліком категорій.

## Конфігурація
- **Провайдер:** Groq Cloud API (`https://api.groq.com/openai/v1/chat/completions`)
- **Модель:** `qwen/qwen3.8-27b`
- **Формат відповіді:** `response_format: {"type": "json_object"}`
- **Температура:** `0.1`; знижує варіативність, але не гарантує детермінованості.
- **Ліміт відповіді:** `max_tokens=200`; таймаут HTTP-запиту до Groq — 15 секунд.
- **Очікувані поля AI:** `category`, `explanation`, `urgency`. Backend додає `disclaimer` через модель відповіді.

Це конфігурація з `backend/ai_service.py`, а не підтвердження поточної доступності моделі у провайдера.

## Терміновість

Дозволені значення: `звичайне`, `увага`, `терміново`. Backend нормалізує текст AI: наявність `термін` дає `терміново`, `уваг` — `увага`, інші значення — `звичайне`. Це програмна нормалізація, а не підтвердження клінічної точності оцінки.

## Перелік категорій
1. `неврологічне`
2. `шлунково-кишкове`
3. `респіраторне`
4. `опорно-руховий апарат`
5. `шкірне`
6. `загальне нездужання`
7. `інше` (fallback)

## Fallback та безпека
- Якщо AI повернув категорію поза списком, вона автоматично замінюється на `"інше"`.
- У разі виключення або мережевого таймауту Groq API, бекенд перехоплює виняток та повертає статус `503 Service Unavailable` без витоку ключів та деталей сервера.
