# Публікація 0.5.1

Користувач дозволив опублікувати актуальний застосунок після звірки ЛР7. Зберігаємо 0.5; нова версія — 0.5.1 / code 6, якщо такий реліз ще відсутній.

1. Перевірити GitHub і локальні зміни. Включити поточний Android-клієнт, його тести, інструкції, UI/архітектурну документацію, CI та локально адаптовані skills із ліцензіями. У Lab5PhoneScenarioTest включити лише необхідну адаптацію конструктора; інші зміни користувача, backend/evaluation/lab2, старі матеріали лабораторних, IDE, приватні файли та звіти не включати.
2. Оновити README й docs/releases/v0.5.1.md. Зберегти список файлів і хеші сторонніх змін локально; перевірити staged-вміст на секрети й приватні шляхи.
3. Створити ізольований snapshot індексу; скопіювати приватну конфігурацію підписання лише в ігноровану build-директорію. Виконати Android unit/lint/release build і backend unit саме для цього snapshot. Нові live перевірки не потрібні: поточний UI й справжній повтор AI перевірені на телефоні під час оновлення звіту.
4. Зафіксувати переглянуті зміни. Повідомлення коміту містить [skip render], щоб публікація Android не оновлювала сервер. Без force-push/переписування історії. Перевірити підпис APK проти 0.5, версію, debuggable=false, zipalign і SHA-256; пересвідчитися, що код APK відповідає коміту.
5. Push main, новий тег v0.5.1, створення draft-релізу, завантаження APK/контрольної суми, перевірка digest, публікація і повторне публічне завантаження. Попередній реліз не змінювати. Телефон із debug не перевстановлювати release із іншим підписом.
6. Записати точний source commit і фактичні результати в журнал/BUILD-INFO. Перевірити CI після push, не видавати очікуваний результат за успішний. Локальний DOCX не публікується.
