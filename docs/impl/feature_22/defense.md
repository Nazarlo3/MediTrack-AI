# Захист ЛР7 — 8–9 хвилин

## Перед захистом

Підключити телефон, запустити локальний backend і `adb reverse` за README. Перевірити `/health`. Використовувати навчальний APK `0.4-lab7`, зазначений у verification.md. Увімкнути інтернет на ПК для Groq. Доступний ліміт/модель залежать від провайдера. Заздалегідь відкрити синтетичні резервні знімки — вони доповнюють живу демонстрацію.

## 0–1 хв — проблема і користувач

«MediTrack AI допомагає користувачу впорядкувати опис самопочуття та вести список прийомів ліків. AI дає загальну категорію й пояснення, але не ставить діагнозу. Мій основний сценарій — описати скаргу, переглянути результат, уточнити його й відкрити збережений запис».

## 1–3 хв — живий основний сценарій

1. Перейти з «Мої ліки» в «Аналіз AI».
2. Ввести: «Вдарив гомілку об край ліжка, болить у місці удару. Рани немає.», тривалість 2, інтенсивність 5.
3. Натиснути «Перевірити», показати loading, пояснення та числа. Відкрити запис історії. Не редагувати базу/JSON вручну.
4. Пояснити: історія зберігається на телефоні, повторне відкриття не витрачає AI-запит.

## 3–5 хв — збій та відновлення

Зупинити **свій локальний** uvicorn через Ctrl+C, залишивши застосунок відкритим. Надіслати синтетичний опис. Показати помилку й «Спробувати ще раз». Запустити ту саму команду сервера, натиснути повтор: результат з’являється без перезапуску застосунку. Цей живий збій відрізняється від контрольованого IOException в автоматизованому тесті — не називати їх однією перевіркою.

Якщо лишається час: «Монітор не працює.» → «Потрібно більше інформації» → уточнення про реальну скаргу. Це HTTP 200 без придатної категоризації, а не збій інтернету. Така відповідь не засмічує історію.

## 5–7 хв — архітектура та розвиток

Показати схему в architecture.md: Compose → ViewModel/controller → use case/repository → Retrofit → FastAPI → AnalysisService/AIProvider → Groq. Історія — SharedPreferences через repository. Ключ тільки на сервері. Окремо існують ліки та AlarmManager.

Від MVP додано KB і керований процес роботи з агентом, терміновість, локальну історію, ліки/нагадування, розділення відповідальностей, уточнення, тривалість та інтенсивність. У ЛР7 завершено поведінку без придатного результату й перевірено інтеграцію.

## 7–9 хв — докази та обмеження

Показати таблицю verification.md та AI SUMMARY.md: які перевірки реальні, які з ін’єкцією помилки, де були повтори. Вісім валідних входів — знаменник категоризації, два невалідні — окрема валідація. П’ять старих прикладів повторено дослівно. Малий набір не доводить медичної точності.

Назвати обмеження: зовнішня модель/ліміти, немає офлайн-AI; до 20 записів і трьох уточнень; контекст не відновлюється після завершення процесу; системні обмеження нагадувань. Наступний крок — контрольоване розгортання та розширення набору оцінювання, без обіцянок клінічної готовності.

## Роль coding agent

Codex підготував код стану NoResult, тести, інструкцію запуску, технічні докази й звіт. Студент погодив план, надав пристрій і має особисто повторити живий сценарій перед захистом. Не приписувати студенту автоматизовані перевірки, яких він сам не виконував.
