## Що перевірено тестами

1. Початково ввімкнений перемикач без підтвердження не дає дозволу; відсутність metadata → жодного запису, сумісний legacy API.
2. Після дозволу — metadata/випадковий request UUID, повний результат і параметри; raw context не зберігається. Відмова у новому запиті повертає legacy шлях.
3. Помилка запису БД не губить відповідь AI, у логах немає тексту exception; disabled/rejected/failed AI не створюють записів.
4. Видалення лише власника capability-token; чужі записи залишаються, пізні запити відкликаного ключа блокуються.
5. Повтор UUID не дублюється; записи старші 90 днів не входять у читання й статистику.
6. Перегляд і статистика недоступні без окремого admin Bearer. Обмежена пагінація, no-store, показники на доступній вибірці. NoResult можна переглянути для оцінювання якості.

## Межі

Backend перевірявся через справжній HTTP TestClient і SQLite, AIProvider синтетичний. Реального Groq, наскрізного Android → оновлений backend → база та візуального UI-тесту цієї функції не виконували. Новий debug використовує локальну адресу 127.0.0.1:18765; сервер із попередньої сесії та Render автоматично не оновлювалися. У хмарі збереження не активоване.

Перед хмарним запуском потрібні постійний приватний диск/відповідна БД, серверні змінні, захист резервних копій і процедура доступу/видалення; див. [інструкцію](../../data-collection.md). Строк фізичного очищення при зупиненому сервері/зовнішніх backup не гарантований цим кодом. Автоматичного навчання немає. Окремі rate limiting/auth користувачів і централізована БД для кількох інстансів залишаються наступними задачами, не видаються за виконані.

Оновлений APK відрізняється від раніше перевіреного APK ЛР7: його хеші та screenshots залишаються історичними. Звіти ЛР7 у цій задачі не переписувалися. Commit, push, production deployment і реліз не виконувались.
