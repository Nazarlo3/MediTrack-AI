# Google Sheets як сховище збору даних

Погоджено 09.11.2026. Наявний collection API і Android не змінюються. SQLite лишається локальним варіантом.

1. Створити backend/sheets_collection_repository.py і sheets_transport.py: OAuth, керовані аркуші «Звернення», «Статистика», прихований реєстр відкликаних ключів. Старі аркуші/дані не видаляти. Вхідні тексти зберігати як текст, не формули.
2. Додати фабрику collection-сховища, параметри GOOGLE_SHEETS_ID/GOOGLE_APPLICATION_CREDENTIALS, google-auth[requests]. Один процес/один worker, без ручного сортування керованих даних під час роботи. Власні записи видаляються разом із відкликанням ключа одним атомарним batchUpdate; serial lock захищає запити в межах процесу.
3. Зберегти згоду, дедуплікацію, 90-денне очищення та адміністративний API. Помилки Google не ламають AI. Не переносити SQLite-історію автоматично.
4. Перевірити backend unit-набір і синтетичний запис/читання/статистику/видалення у наданій таблиці. Ключі/токени не друкувати. Тестові тексти видалити після перевірки, реєстр відкликаних тестових ключів лишити як захист від повтору.
5. Оновити docs/data-collection.md, README/API/архітектуру та журнал. Render, commit/push/реліз не виконувати.

Уточнення: місце зберігання змінилося на Google, тому Android-діалог і CollectionConsent/DataCollectionSettings оновлюються до згоди 2. Вимкнений вибір зберігається. Згода 1 залишається сумісною з SQLite, але не дає дозволу на Google.
