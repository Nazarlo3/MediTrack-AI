# Google Sheets — журнал

- 09.11.2026: перевірено доступ HTTP 200 до наданої таблиці; JSON-ключ у private-data виключений із Git. Таблиця містила лише «Аркуш1». Погоджено адаптацію, створено план; перевірки реалізації ще не виконані.
- Реалізовано SheetsCollectionRepository/SheetsTransport, фабрику й очищення обраного сховища. Ключ тільки в серверному secret file, OAuth-токен у пам’яті; дані/статистика та видалення/відкликання змінюються атомарним batchUpdate. Джерело гарантії атомарності — офіційні Google Sheets API batchUpdate docs. Нові дані не мігруються зі старого SQLite.
- До runtime додано google-auth[requests]. Стандартний transport requests, додатковий curl для локального повільного DNS: секретні тіла/заголовки через stdin, TLS не послаблюється. Local .env налаштовано без виведення/зміни Groq-секрета; Google-ID не зашитий у код.
- Реальна Google-таблиця підготовлена: «Звернення», «Статистика», приховані ключі; старий аркуш збережено. Два повні синтетичні прогони пройшли; тексти прибрано. Початкову невдалу ініціалізацію зафіксовано, причина невідома. Подробиці — verification.md/json.
- Повідомлення Android прямо називає Google і межі очищення/історії версій. Потрібний повторний явний вибір версії 2; версія 1 не включає Google-збір. Вимкнений попередній вибір не вмикається автоматично. Фактична версія записується в обох сховищах.
- Backend 59 тестів успішні; Android unit/build/lint пройшли. Документація/API/архітектура/README та план актуалізовані. Немає нового release/commit/push/Render; старий локальний сервер не перезапускався. Для фактичного приймання звернень користувачів потрібне застосування коду/налаштувань на сервері й оновлений Android.
- Фінальний перегляд: ліміт ключового реєстру блокує новий збір, але не видалення; додано тест, окремий Sheets-набір 9/9 успішний. Google-історію версій видалення рядків не очищує; це зазначено в UI та документації.
