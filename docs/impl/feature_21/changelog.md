## Відбір і перевірки

- Переглянуто diff реалізації/тестів/документації, усі 79 змінених і нових файлів перевірено на наявні серверні секрети та типові формати credentials без виведення значень. Ключів не виявлено; підозра email у `this@SymptomRepositoryTest.request` була лише Kotlin qualified-this, це перевірено. Це перевірка поточного набору, не аудит усієї давньої Git-історії.
- Для спільних `Lab5PhoneScenarioTest.kt` і `docs/testing.md` сформовано вміст тільки ЛР6; ЛР2/ЛР3 та всі інші невідібрані файли залишаються в робочій папці. Збережено SHA-256 до операцій. Повний перелік коміту — [files.md](files.md).
- Кандидат відтворено як HEAD + відібрані файли в ізольованій копії. Початковий запуск процесів не відбувся через права доступу Python temp-директорії; жодних результатів тестів з нього не заявлено. Копію створено зі звичайними успадкованими правами; залежності не встановлювалися.
- Backend: `python -B -m unittest discover -s backend/tests -v` у наявному lab5-venv — **38 tests OK, 0,292 с**, exit code 0. Сторонній пізніший тест ЛР3 до кандидата не включений.
- Android: `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest --offline` — **BUILD SUCCESSFUL in 1m 5s**, **61 тест, 0 failures/errors/skipped**, усі 81 Gradle-задачі виконано, не UP-TO-DATE. Lint — **0 errors / 44 warnings**. APK створені тільки локально для перевірки; не встановлювалися й не публікувалися.
- `--suite details` і `--suite legacy` evaluator пройшли dry-run: по 10 прикладів і дві конфігурації, без мережі. Наявні 20 первинних HTTP 200 та телефонний сценарій 11,814 с перевірені як збережені докази, без нових Groq/телефонних викликів.
- Відомі попередження TabRow/Starlette залишені; клінічну точність, опублікований release 0.3 і Render ці перевірки не підтверджують. [Структурований результат](verification.json).
- Звичайний cached whitespace-check позначив тільки завершальні порожні рядки у чотирьох збережених `mobile-attempt-*.txt`. Сирі логи не переписували; усі інші staged-файли проходять `git diff --cached --check`. Жодних помилок whitespace в коді немає.

## Коміт і звіт

Код та документи цього набору призначені одному локальному коміту `feat(ai): add symptom duration and intensity for Lab 6`. Повний хеш визначається після commit і додається до локального Word-звіту `_v2`; записувати його всередині того самого коміту неможливо без циклічного самопосилання. Методичка звірена: у звіті мають лишитися варіант А, поля/межі, пороги до реалізації, порівняння baseline/current, результати, внесок AI, ідентифікатор commit й обмеження відсутніх точних п’яти історичних вводів ЛР4. Погоджені редакційні зміни звіту збережено; various files лишається локальною папкою.

## Поновлення дозволу та остаточна звірка

- Початкова спроба commit була скасована користувачем до його створення. Після виправлення звітів користувач повторно підтвердив план локального коміту ЛР6 та додавання хешу до звіту `_v2`.
- Повторно звірено всі 55 staged-шляхів із погодженим переліком; перевірка відомих локальних ключів і типових форматів credentials не виявила секретів. Значення ключів не виводилися.
- Увесь staged-код, JSON і сирі протоколи побайтово відповідають перевіреному кандидату з урахуванням CRLF/LF. Хеші журналів backend/Android збігаються з verification.json. Результати 38/61 та lint 0/44 повторно підтверджено за журналами; нових тестів і зовнішніх AI-запитів не запускали, оскільки код не змінювався.
- Оновлено лише шлях до перейменованого звіту й записи Git-оформлення. Невідібрані робочі зміни, локальні налаштування та приватні матеріали не додаються. Push, реліз і розгортання не входять до дозволеного кроку.
