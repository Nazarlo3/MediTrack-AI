# План реалізації Feature 1: Оцінка терміновості та Історія перевірок

## 🎯 Мета функції
Розширення базового MVP мобільного асистента MediTrack AI двома новими функціональними можливостями:
1. **Автоматична оцінка рівня терміновості симптому (Urgency Level Assessment):** Штучний інтелект визначає ступінь небезпеки стану (`"звичайне"`, `"увага"`, `"терміново"`). Мобільний додаток відображає відповідну кольорову позначку (зелений / помаранчевий / червоний).
2. **Локальне збереження історії перевірок (Symptom History Storage):** Автоматичне збереження всіх запитів користувача та відповідей ШІ в локальне сховище пристрою (`SharedPreferences` + Gson) для усунення обмежень Лабораторної роботи №2.

---

## 📐 Покроковий технічний план (Feature Roadmap)

### Крок 1: Оновлення бекенду та AI-промпту (Backend & AI)
- Розширення Pydantic-моделі `SymptomResponse` полем `urgency`.
- Модифікація `SYSTEM_PROMPT` у `ai_service.py`: додавання суворих правил градації небезпеки для травм голови, застуди та звичайних симптомів.
- Нормалізація відповідей від Groq AI API (`qwen/qwen3.8-27b`).

### Крок 2: Оновлення мобільного додатка (Android Client)
- Додавання поля `urgency` та класу `SymptomHistoryItem` у `SymptomModels.kt`.
- Переведення `SymptomViewModel` на `AndroidViewModel` із локальним збереженням історії в `SharedPreferences`.
- Відображення кольорових значків терміновості у `SuccessCard`.
- Додавання списку `HistorySection` із відображенням часу, опису, категорії, статусу терміновості та повного пояснення ШІ.

### Крок 3: Надійність та холодний старт (Reliability)
- Збільшення мережевих таймаутів у `ApiClient.kt` до 60 секунд.
- Додавання текстової підказки для користувача під час прокидання сервера Render.

## ✅ Критерії готовності (Definition of Done)
- ШІ правильно класифікує травми та небезпечні стани як `"терміново"`.
- В UI виводиться кольоровий badge залежно від рівня небезпеки.
- Історія зберігається на дисці та відновлюється при перезапуску додатку.
- Наявна кнопка очищення історії.
