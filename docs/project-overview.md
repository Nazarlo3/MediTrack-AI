# Project Overview — MediTrack AI

## Проблема
Пацієнтам та користувачам часто важко швидко зорієнтуватися, до якої саме медичної сфери належать їхні симптоми, що призводить до невизначеності перед первинним зверненням.

## Користувач
Приватні особи, які бажають отримати первинну інформаційну категоризацію своїх неідентифікаційних описів симптомів без медичної діагностики.

## Основний сценарій
1. Користувач вводить у мобільному застосунку текстовий опис самопочуття.
2. Застосунок передає запит через REST API на FastAPI (Render або локально для ЛР7).
3. Сервер обробляє опис та викликає Groq AI (модель Qwen 27B).
4. Результат (категорія + пояснення + терміновість + застереження) повертається на мобільний екран у вигляді кольорової картки та зберігається в локальну історію до 20 записів.

Окремо реалізовано локальний список препаратів із фото, статусом прийому за датою та локальними нагадуваннями за часом, днями й кінцем курсу. Для доставки потрібні системні дозволи; перевірки описано в `testing.md`.

## Межі MVP
- Інформаційний характер: додаток НЕ ставить діагнози і НЕ дає рецептів.
- Обмежений фіксований список із 16 категорій.
- Працює з безкоштовним хмарним запускom backend на Render.com та Groq Cloud API.

## Поточне доповнення

Необов’язкові тривалість 1–30 днів та інтенсивність 0–10 передаються моделі й зберігаються в історії/уточненнях. У ЛР7 has_usable_result=false показує брак інформації з питанням і не створює завершеного запису. Локальний debug URL задається при збірці; запуск і перевірки — README та [feature_22](impl/feature_22/verification.md).
