# Правила для документації MediTrack AI

Область дії: docs/ та її підпапки. Загальні правила розробки, безпеки, Git і перевірок містяться в [кореневому AGENTS.md](../AGENTS.md); тут лише доповнення для документації.

- Пиши коротко, українською, узгоджено з поточним кодом. Посилайся на конкретні файли/класи/маршрути; відрізняй факти, рекомендації та невідомі деталі.
- Перед створенням документа перевір наявний матеріал і онови його, якщо він уже покриває задачу. Не переписуй сторонні документи й не створюй паралельні копії.
- Після суттєвої зміни поведінки підтримуй відповідні архітектурні/API-документи; важливі рішення та їхні відомі причини фіксуй там, де майбутній розробник їх знайде.
- Плани, ченджлоги та докази веди в docs/impl/ для відповідної задачі. Позначай історичні зрізи; старі результати тестів не є новою перевіркою. Не вигадуй логи, промпти, коміти чи результати.
- Матеріали лабораторних і звіти в docs/various files/ — локальні файли користувача. Не змінюй їх заради задачі з кодом без запиту; використовуй синтетичні приклади замість реальних медичних записів.
- На Windows architecture.md / ARCHITECTURE.md та decisions.md / DECISIONS.md позначають ті самі файли. Використовуй наявні назви; перевіряй регістр посилань також для GitHub/Linux.
- Перед завершенням перевір локальні посилання, узгодженість документів із кодом і diff. Для змін лише тексту не запускай Android-збірку чи backend-тести.
