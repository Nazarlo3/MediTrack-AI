# Architectural Decisions — MediTrack AI

## Прийняті рішення та причини

### 5. Перехід до статусу прийому за датою без втрати старого списку
- **Причина:** старий прапорець `isTaken` не містив дати. Новий формат пишеться в `medications_list_v2`, а старий ключ лишається для відновлення; старе значення без дати не означає прийом сьогодні.
- **Збереження:** операції виконуються послідовно через `LocalDataStore`; новий стан показується після успішного запису.

### 1. Використання FastAPI (Python) замість прямого виклику Groq з Android
- **Причина:** Безпека. Сховати API-ключ `GROQ_API_KEY` на сервері в змінних середовища `.env`, унеможливлюючи його витік чи декомпіляцію через мобільний APK.

### 2. Хостинг Render.com для бекенду
- **Причина:** Публічна HTTPS-адреса без прив'язки до локальної Wi-Fi IP-адреси ноутбука розробника. Доступність не гарантована, можливий холодний старт.

### 3. Модель Groq `qwen/qwen3.8-27b`
- **Реалізація:** У коді задано цю модель та режим `json_object` для структурованої відповіді з категорією, поясненням і терміновістю. Це фіксує вибір у проєкті, а не порівняння якості, ціни чи поточної доступності моделей.

### 4. Збільшення таймаутів OkHttp до 60 секунд
- **Причина:** Дати більше часу на холодний старт Render. За довшого очікування або недоступності мережі все одно можлива помилка таймауту.

### 6. Локальні нагадування через AlarmManager

- **Причина:** Графік уже зберігається на пристрої й повинен працювати без інтернету. Один наступний alarm обчислюється за календарем, а не інтервалом 24 години, щоб врахувати дні тижня та часовий пояс.
- **Дозволи:** `SCHEDULE_EXACT_ALARM` перевіряється окремо від `POST_NOTIFICATIONS`. За відсутності точного доступу використовується приблизний alarm з явним попередженням у UI.
- **Сумісність:** Час читається зі збереженого `mealSlot`; модель та API не змінюються. Старим записам без часу не призначається довільна година.
- **Скасування та відновлення:** Стабільний Intent URI містить повний ID препарату; повідомлення використовує ID як tag. Системні події відновлюють майбутній графік. Службові метадані й глобальний Mutex обмежують дублювання; гарантії доставки «рівно один раз» немає.
