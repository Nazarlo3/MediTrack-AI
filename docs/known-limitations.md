# Відомі обмеження MediTrack AI

Поточний стан 04.11.2026. Фактичні перевірки ЛР7 — [verification.md](impl/feature_22/verification.md); історія — testing.md та журнали feature_*.

- **AI інформаційний.** 16 категорій і три urgency не є діагнозом. Незалежного клінічного механізму тріажу немає. Малий синтетичний набір перевіряє категорії/контракт, не медичну точність. Тривалість/інтенсивність — самооцінка, не діагностичні пороги.
- **Зовнішня доступність.** Groq, модель і квоти можуть бути недоступні. У ЛР7 були технічні 503 з окремими успішними повторами; конкретний HTTP-статус зовнішнього провайдера не збережений. Немає автоматичних повторів/резервної моделі/офлайн-AI. Render може мати cold start; Android connect/read/write timeout 60 с не гарантує доступності.
- **NoResult.** Явне has_usable_result=false відрізняється від технічного збою й не потрапляє до історії. Визначення придатності також залежить від LLM. Відсутнє поле старого сервера зберігає стару поведінку, а не гарантує нову семантику. Для ЛР7 потрібні обидва оновлені компоненти.
- **Локальні дані.** До 20 завершених перевірок, без облікових записів/синхронізації/експорту. SharedPreferences не мають окремого шифрування; backup дозволений без явних виключень. Видалення застосунку стирає дані. У старих записів повна дата невідома.
- **Пошкоджені дані.** readError блокує запис, автоматичного ремонту немає. Історія кешується в екземплярі; це не загальна транзакційна БД. Старі ключі ліків є резервним знімком, а не синхронною копією v3; відкат може показати старі дані.
- **Життєвий цикл.** Форми зберігаються через rememberSaveable, ViewModel переживає зміну конфігурації. Контекст/last request/Job не відновлюються після завершення процесу. Cancel не гарантує зупинки вже прийнятого сервером обчислення. Після завершення аналізу кнопку cancel не застосовують до запису історії.
- **Нагадування.** До 12 часів на препарат, відкладення лише в межах тієї самої дати. Потрібні сповіщення; без точного alarm можливі затримки. Force stop/обмеження Xiaomi можуть блокувати доставку. Пропущені прийоми не надолужуються; маркер delivered перед notify залишає ризик пропуску при аварії, немає гарантії рівно одного показу.
- **Межі перевірки пристрою.** ЛР7 перевіряє встановлення сумісного debug через install -r, реальний AI/історію, повтор, NoResult, дублювання й CREATED→RESUMED. Помилки IOException/503 ін’єктовані явно. Не підтверджено process death/reboot/next-day/timezone та інсталяцію нового release. F07 пройдено 05.11.2026 після ручного вимкнення сповіщень; Xiaomi забороняє shell revoke. Повернення дозволу та збіг початкових хешів даних підтверджено 05.11.2026.
- **Конфігурація.** Локальний debug потребує ПК з backend/інтернетом та ADB reverse або LAN; адреса задається при збірці, не в UI. Release 0.4 має інший підпис від debug. ЛР7 не публікує новий реліз і не розгортає Render.
- **Технічний борг.** Довжина опису до/після trim різниться між API й Android. Python runtime-залежності не закріплені, CI відсутній. Публічний backend не має власної auth/rate limit. Cleartext дозволений у Manifest. Повного аудиту історії Git на секрети не виконували.
