# Requirements — MediTrack AI

## Реалізовані вимоги
1. **Мобільний UI (Android / Jetpack Compose):**
   - Текстове поле для вводу симптому з валідацією на порожній ввід.
   - Відображення станів `Idle`, `Loading`, `Success`, `Error`.
   - Інформаційна підказка про холодний старт хмарного сервера під час завантаження.
   - Можливість повторного запиту при помилці без перезапуску застосунку.

2. **Backend API (FastAPI / Python):**
   - Ендпоінт `GET /health` для перевірки статусу.
   - Ендпоінт `POST /analyze-symptom` з валідацією Pydantic (`min_length=3`, `max_length=500`).
   - Контрольовані HTTP-помилки (`400 Bad Request`, `503 Service Unavailable`) без витоку деталей коду чи ключів.

3. **AI-Інтеграція (Groq API):**
   - Використання моделі `qwen/qwen3.8-27b`.
   - Суворий формат відповіді `json_object` з обов'язковими полями `category` та `explanation`.

## Незавершені функції (план для розширення)
- Оцінка рівня терміновості (Urgency Level) з відповідним кольоровим кодуванням UI картки.
- Збереження історії перевірок симптомів локально на пристрої.

## Критерії готовності (Definition of Done)
- Код успішно компілюється в Android Studio без помилок.
- Backend відповідає на розгорнутому у хмарі сервері Render.
- Всі сценарії обробки помилок відпрацьовують стабільно без аварійних завершень (crashes).
