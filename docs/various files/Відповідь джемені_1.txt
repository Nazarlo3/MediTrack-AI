3. Знайдені проблеми
1.
Конфігурація середовища для CLI Gradle:
◦
Під час стандартного запуску .\gradlew.bat у терміналі відсутня змінна JAVA_HOME у замовчувальному оточенні PowerShell.
◦
Виявлено конфлікт системних змінних ANDROID_PREFS_ROOT та ANDROID_USER_HOME, що викликало помилку ініціалізації Android Gradle Plugin (AndroidLocationsBuildService). При використанні JDK Android Studio та очищенні ANDROID_PREFS_ROOT збірка проходить повністю успішно.
2.
Покриття тестами:
◦
Для SymptomViewModel, LocalDataStore та FastAPI ендпоінтів відсутні окремі автоматичні unit-тести (перевірка виконувалася через аналіз коду).
4. Що лишилося перевірити на телефоні (неперевірені ручні сценарії)
Примітка: Повідомлений користувачем результат про отримання одного production-повідомлення у згорнутому стані зафіксовано, проте інші фізичні сценарії залишаються неперевіреними:
1.
Перезавантаження телефона: Створити нагадування на майбутній час, перезавантажити телефон і перевірити, чи спрацює ReminderRestoreReceiver та чи надійде сповіщення.
2.
Відмова в дозволах: Скасувати дозвіл точного часу (SCHEDULE_EXACT_ALARM) або сповіщень. Перевірити, що UI відображає картку з поясненням і кнопкою переходу в налаштування, а застосунок не падає.
3.
Два препарати на один час: Перевірити, що надходять обидва сповіщення (різні ID PendingIntent) і жодне не губиться.
4.
Зміна часового поясу / системного часу: Змінити часовий пояс пристрою та перевірити, що нагадування адаптуються під місцевий час.
5.
Завершений курс та старий формат: Додати препарат із датою закінчення в минулому або форматом часу без HH:mm (наприклад, "перед обідом") і переконатися, що нагадування не плануються, а в картці є пояснення.
6.
Release-збірка: Установити release APK та перевірити роботу нагадувань без активного DebugMenu.
